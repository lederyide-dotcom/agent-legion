# 頂尖作法提案（frontier-proposal-tw）

> 作者 **DavidY-tw**　│　AI 協作 Claude

目的：使用者問「這件事怎麼做到最好」時，不要直接動手，也不要只丟一句意見。先把限制與事實弄清楚，再給一份能直接拍板的提案；拍板後才實作。

## 何時用

- 使用者說：頂尖作法、最佳實務、業界怎麼做、你的看法、AI 最大潛能、做到最好、做得更美觀或更專業
- 使用者要一個「效果」但沒指定技術（例如「要有動態效果」「兩邊要統一」「手機也要方便看」）
- 一個決定會影響多個平台、多個 repo，或之後很難改

很小、做法只有一種的事（改字、修一個 bug）不用這個流程，直接做。

## 流程

### 1. 一句話重述目標
寫出使用者真正要的結果與受眾，例如「GitHub 與 Obsidian 看到同一張會動的流程圖，手機也能看」。不確定就列 2～3 種理解，用選項問。

### 2. 查清限制與事實（表格）
每個相關平台或環境一列：能做什麼、不能做什麼、依據。

| 平台 | 能做 | 不能做 | 依據 |
|---|---|---|---|

- 能在本機查的就自己查（讀程式、跑指令、看版本、開瀏覽器試），不要叫使用者去查。
- 沒查證的寫「未驗證」，不要用常識猜。
- 版本會變的事（例如某平台內建的函式庫版本）特別標出來，提案不要依賴它。

### 3. 領域頂尖作法（5～7 條）
每條一句做法＋一句為什麼，選和這件事真正相關的。常用的面向：

- **單一來源**：定義一次，各平台的輸出都由它產生，並用測試擋下不一致
- **有意義**：效果要傳達資訊（方向、狀態、真實資料），不是裝飾
- **靜止時就完整**：動畫、載入、腳本失效時內容仍然完整可讀
- **無障礙**：減少動態、替代文字、亮暗配色、手機寬度
- **新鮮度看得見**：快照標資料時間，由排程或指令自動重產，不靠手動
- **輕量與可維護**：選最小、最穩的技術，避免綁定會變的版本
- **分層**：摘要給一眼看懂，細節連到可互動的地方

### 4. 推薦方案＋替代方案
- 推薦方案寫清楚：做什麼、輸出在哪、怎麼保持同步、怎麼驗證。
- 列 1～2 個替代方案，各一句取捨（例如「最快但不會隨資料更新」）。
- 寫出花費（API 額度、真錢）、預估時間、風險；風險裡沒驗證過的標「未驗證」，並寫做完後怎麼驗證。

### 5. 讓使用者一鍵決定
- 用選項視窗（AskUserQuestion）或代號（A／B／C），推薦項放第一個並標「推薦」。
- 一次有多個決定就分題問，不要讓使用者打長文字。
- 碰到使用者規定「必須先問」的事（花錢、刪除、改全域設定、安裝技能或外掛、對外發布），在選項裡寫明。

### 6. 決定後交棒
- 小項目直接實作；大項目先依 spec-handoff-tw 寫 spec，再交給 autonomous-dev-loop。
- 實作完：自己驗證（含實際渲染或實際執行，不只跑單元測試）、交 code-reviewer 審查、修必修項目、證據寫進 02_data。
- 回報時分清「已實測」與「未驗證」，例如「瀏覽器實測正常，GitHub 頁面未驗證（私人 repo，瀏覽器沒登入）」。

## 輸出格式

```
## 結論
<推薦方案一句話＋為什麼>

## 先講限制
| 平台 | 能做 | 不能做 | 依據 |

## 頂尖作法
1. <做法>：<為什麼>
…

## 建議方案
- 做什麼／輸出在哪／怎麼同步／怎麼驗證
- 花費：…　時間：…
- 風險（未驗證）：…

<選項視窗或代號：A 推薦／B／C>
```

## 守則

- 結論先講，細節在後；不要長篇比較所有可能。
- 不編造數字、版本或「業界都這樣做」；說不出依據就標未驗證。
- 推薦要落地：寫得出驗證方式才算推薦，寫不出的降為替代方案。
- 尊重已有的設計與規則：沿用專案現有的單一來源、色票、命名、證據格式。
- 做完後回顧一次：哪個假設錯了、下次提案要先查什麼，寫進該專案的 lessons 或記憶。

## 實例（agent-legion，2026-11-15）

使用者：「將 Obsidian 流程、儀表以動態效果呈現，GitHub README 也要同步支援動態效果，提出這類領域頂尖作法與看法」

- 限制：GitHub README 不執行 JavaScript；Obsidian 的 Canvas、Bases 沒有動畫；兩邊都能顯示「內含 CSS 動畫的 SVG 圖片」；GitHub 與 Obsidian 內建的 mermaid 是否支援連線動畫語法，版本無法確認，標為未驗證，不依賴。
- 推薦：從單一定義產生動態 SVG（連線流動＋重播真實任務 T-0022 的路徑＋KPI 卡），兩邊嵌入同一個檔案；替代方案：只做流程、或錄 GIF。
- 使用者選 A。實作後瀏覽器實測動畫時間窗；審查抓到「實線被 mermaid 樣式蓋掉不會流動」→ 修正並加測試。教訓：CSS 注入要放在原有樣式之後，並在瀏覽器量實際生效的樣式，不能只看原始碼。
