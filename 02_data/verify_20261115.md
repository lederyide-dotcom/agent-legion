- 做法：`src/legion/bench.py` 在獨立 schema `bench`、`.legion_tmp/bench` 的 vault 與 worktree，用 mock 跑 8 道固定題目：
  - `low`：一次就過，人工介入 0。

## 2. 改檔防護：排除「Bash 把 \n 改壞」與「write_text 把 LF 改成 CRLF」（David 選 A 四層全做、舊檔一次轉 LF）

- 根因（實測）：
  - 同一段內容經 Bash 工具傳送，`'C\\nD'` 會少一層反斜線變成 `'C\nD'`；Write 工具一字不差。所以「Bash heredoc 包 Python、Python 字串裡再包程式碼」必壞，而且壞法看寫法而定。
  - Python `Path.write_text` 與 csv 寫入器在 Windows 預設寫 CRLF。
  - repo 原本只規定 .bat、.ps1，已有 14 個檔是 CRLF 或混合換行。
- 處理：
  1. 記憶規則：寫檔一律走 Write／Edit；批次修改腳本也用 Write 寫成檔、替換內容不寫成字串常值。
  2. 2ca4f0e：src 與 scripts 共 44 處寫檔改成 LF（`newline="\n"`、`lineterminator="\n"`）。
  3. e3b4566：`.gitattributes` 改為 `* text=auto eol=lf`，14 檔只改換行。`git diff --cached --ignore-cr-at-eol --stat` 只剩 .gitattributes；`git ls-files --eol` 已無 crlf／mixed。列入 `.git-blame-ignore-revs`。
  4. `scripts/check_text_files.py`：檢查 CRLF、.py 能否編譯、整檔只改換行。由專案層級 Claude hook（`.claude/settings.json`，PostToolUse）在每次寫檔或執行指令後跑；由 `.githooks/pre-commit` 在提交前跑，並加上 ruff 與 `legion docs --check`。已設定 `core.hooksPath=.githooks`、`blame.ignoreRevsFile`。
- 實測：
  - 經 Bash 寫出 CRLF 探測檔與斷行字串探測檔 → Claude hook 當場回報兩項。✅
  - 暫存後 `git commit` → pre-commit 擋下（rc=1，HEAD 不變）；探測檔已刪除。✅
- 測試：`tests/test_text_files.py` 3 項（含「repo 內 .py 全為 LF 且可編譯」）。✅
- 審查（code-reviewer）：2ca4f0e 沒改壞語意、e3b4566 逐檔比對確實只改換行。🔴 2 項已修：
  1. 中文檔名被跳過：git 預設 core.quotepath 會把中文路徑跳脫，檢查程式找不到檔就略過。改為一律 `git -c core.quotepath=false … -z`，並加測試：用真的未追蹤檔「zz_測試 檔名.md」驗證會被抓到。
  2. pre-commit 會擋住 legion 在 `.worktrees/` 的自動提交（worktree 沒有 .venv）。改為找不到時退回主 worktree 的 .venv（`git rev-parse --git-common-dir`），並優先載入該 worktree 的 src 再跑 `legion docs --check`。
