### 1.3 建議的模組結構

**【推測】** 在 agent-legion 內新增一個純函式模組，與 CLI 分離，方便單元測試：

```
legion/checks/
  __main__.py     # argparse 分派（既有）
  report.py       # 既有：章節、長度
  report_rules.py # 新增：三個純函式，輸入文字、回傳違規清單
```

三個規則函式：

| 函式 | 檢查 | 回傳 |
|---|---|---|
| `check_risk_section(text)` | 是否有標題含「其他風險」 | 違規清單 |
| `check_findings_have_refs(text)` | 每個「發現」是否附 `檔案:行號` | 缺少引用的行號清單 |
| `check_findings_have_tags(text)` | 每個發現是否有 `【事實】` 或 `【推測】` | 缺少標記的行號清單 |

「發現」要先定義，否則無法檢查。**【推測】** 建議定義為：清單項目（`- ` 或 `* ` 或 `1. ` 開頭）中，含 `【事實】` 或 `【推測】` 的那一行，加上表格資料列。理由是純標題與說明文字不是發現，全部要求引用會造成大量誤報。

### 1.4 建議的 CLI 介面

```
python -m legion.checks report <file> [--section NAME ...]
    [--require-refs] [--require-tags] [--require-risk-section]
    [--strict]            # 等同三者全開
    [--lenient]           # 違規只警告，不影響結束碼
```

- `--require-refs`：每個發現要有 `檔案:行號`。
- `--require-tags`：每個發現要有 `【事實】` 或 `【推測】`。
- `--require-risk-section`：等同自動加上 `--section 其他風險`。
- 結束碼：0 通過，1 檢查失敗，2 用法錯誤。這點要與既有行為對齊，**【推測】** 既有行為大概是 0／1，需要在實作時確認。

### 1.5 正規表示式草案

規格給的草案：

- 行號：`[\w./\\-]+\.\w+:\d+(-\d+)?`
- 標記：`【事實】|【推測】`

**【事實】** T-0008 報告就是以這種格式引用的，例如 `easyocr:264-293`、`train:40`（見 `D:\202611_agent-legion\vault\AI\reports\T-0008-report.md:29`、`:50`）。其中有兩種寫法草案**抓不到**：

1. 簡寫引用 `easyocr:264-293` 沒有副檔名，不符合 `\.\w+`。
2. 表格內引用 `（:185-426、:428-481）` 只有冒號與數字（見 `T-0008-report.md:16`），也不符合。

**【推測】** 因此要先決定政策：是要求完整路徑（嚴格），還是接受簡寫（寬鬆）。我建議分兩級：

- 嚴格：`(?<![\w/])(?:[A-Za-z]:)?[\w./\\-]+\.\w{1,6}:\d+(?:-\d+)?(?![\w:])`
- 寬鬆：嚴格規則，或同一報告中已出現過該 basename 的簡寫 `\b\w+:\d+(?:-\d+)?\b`。

預設用嚴格；舊報告（見第 4 節）用寬鬆。

## 4. 向後相容策略

1. **預設關閉。** 不給新旗標時，行為與現在逐字相同（案例 24）。
2. **分階段升級。** 第一階段只加旗標；第二階段 runner 對新任務加上 `--require-refs --require-tags`；第三階段才考慮預設啟用。**【推測】** 這樣舊報告不會突然驗收失敗。
3. **以報告檔頭啟用。** 允許報告第一行附加 `<!-- legion-report: v2 -->`，只有帶這個標記的報告才自動套用嚴格規則。舊報告沒有標記，維持舊規則。這比用日期或任務編號切分更明確。
4. **警告優先。** 新規則先以警告輸出，累積一至兩輪任務後再轉為失敗。
5. **回歸夾具。** 把 `T-0008-report.md` 複製進 `tests/fixtures/`，確認在寬鬆模式下零新增失敗。**【事實】** T-0008 採用「檔案:行號」搭配簡寫（`T-0008-report.md:16`、`:29`），所以嚴格模式下它大概會失敗；因此簡寫必須在寬鬆模式被接受。
6. **訊息可讀。** 每筆違規輸出「行號＋原因＋建議寫法」，讓作者能一次改完。
